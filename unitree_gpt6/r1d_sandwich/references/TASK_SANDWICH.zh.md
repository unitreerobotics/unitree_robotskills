## 任务与准备

右手从烤面包机里取一片面包片，平放到白盘上。左手从小碟里夹起生菜，放到面包片上。右手再取第二片
面包片，盖在生菜上。

每个路点都是明确的 TCP 位置和 rpy，由服务用自带的 IK 求解。不要在真机上使用检测器、符号规划器或
位姿搜索。

开始之前：

1. 阅读 [PLAYBOOK.zh.md](PLAYBOOK.zh.md)，尤其是姿态、安全和命令规则。
2. 取得用户对本次运动的明确授权。
3. 确认操作员在场、工作区已清空、硬件急停触手可及。
4. 只启动已授权的模式。真机运行用：

```bash
bash r1d serve --real --fixed-lift 0.522
```

5. 检查 `state`。双手都必须高于 `z = 0.70`，腰接近 `0`，机器人未处于停止状态。记录起始电机
   温度。
6. 创建运行，把机器人调到起始姿态，并开始录像。`prepare` 把升降调到 `0.522`，并让头部低头到 `0.486` rad；
   头部平视时相机看不到桌面靠近机器人的那一半。在它的输出里核对 `lift_m` 和 `head_pitch`：

```bash
bash r1d eef new
bash r1d eef prepare
bash r1d eef rec-start
```

7. 从当前场景读取头部视图和两个腕部视图。不要复用昨天的物体坐标。

8. 检查烤面包机。两个槽都有面包片时，先取左边那片，放完生菜后再取右边那片。只有一片时，在进入
   第二片面包片阶段之前，请操作员把第二片面包片放进左槽，露出约 `3` 厘米。

### 盘子距离限制

本路线要求盘子中心在 `x >= 0.33`（后盘沿在 `x >= 0.22`）。第一次运动前，从头部图像读出后盘沿。
盘子更近时，先请操作员挪动盘子再开始。

盘子中心在 `(0.284, -0.02)` 时，松手点和推盘起点都不可达，那次运行被放弃；在 `(0.341, -0.026)`
时同样的命令可以执行。数据见 [EXPERIENCE.zh.md](EXPERIENCE.zh.md)。

烤面包机的障碍盒是硬障碍。挪动烤面包机后，用 `look --mark` 重新画出四个角，核对已登记的障碍盒
后再靠近。TCP `0.790` 是夹取下限；不要下降到离烤面包机更近的位置。

## 路线速览

这是运行 `20261125-162207-real-eef-cc`（没有被拒绝，每样东西夹取一次）的路点序列，按“每一步是
一轮”分组：一条先运动再看图的 shell 命令，加上同一轮里对 `runs/latest/<cam>.jpg` 的读取。下面每个
路点都在那次运行中在机器人上执行过。分组方式是新的：那次运行在这些步骤上用了 38 次模型调用，因为
第 3 步是两条命令，而且每张图片都是在单独的一次调用里打开的。按这种分组的运行还没有实测过。

坐标是当天场景的，用来说明每个动作的形状。每个位置都要从当前图像读取。表格后面的说明给出每一步
的限制。这些限制背后的测量数据，以及此前用过的路线，见 [EXPERIENCE.zh.md](EXPERIENCE.zh.md)。

缩写：`J` 关节插值（`"linear": false`），`L` 直线，`g` 夹爪值。

## 面包片说明

### 找面包片（第 2 步）

- 用右腕视图选面包片。头部相机斜着看烤面包机，偏差有几厘米；2026-11-25 按它的投影，手落在了两片
  面包片之间。
- 两片面包片都在两指之间时，绝不能下降。两个槽都有面包片时，两片的中心距约 `4.9` 厘米。
- 让手转向面包片的方向，而不是槽的方向：面包片在槽里可能是斜的。一片 `2` 厘米 厚的面包片在指垫长度
  范围内歪斜 `10` 度时，两指之间需要约 `2.7` 厘米。
- 测量歪斜时，用 `look --cams right_wrist --z 0.785 --mark`，标记点沿手的轴线排列，分别在 TCP 处
  及其两侧各 `2.3` 厘米 处。从近端标记到远端标记，面包片中心都必须落在标记点上。
- 手要沿面包片往后收：TCP 最多只能越过面包片近端 `3` 厘米。手指只有前 `6` 厘米（指垫）能跨在面包片
  两侧。在 TCP 后方 `3.7` 到 `5.7` 厘米处，手指滑块横跨夹爪的整个宽度 `7.8` 厘米，会压在面包片顶上。征兆是
  手停在目标上方约 `1.5` 厘米（目标 `0.79` 时停在 `0.805`），夹取开度为 `0.02`。2026-11-26 因此夹空了五次，
  直到把手从 `x = 0.56` 退到 `0.48`，当时面包片的近端在 `x = 0.46`。近端的位置要从它后方 `2` 到 `3` 厘米处拍的
  腕部视图里找。
- 靠近时的开度：两片都在时 `0.42`，只有一片时 `0.6`。
- 只根据 `z = 0.82` 或 `0.805` 的低位视图判断位置。`z = 0.87` 的视图里，面包片显得比实际近约 `5` 厘米，
  横向误差也被低估：`40` 像素实际是 `1.5` 厘米。
- 第一片取出后，重新读剩下那片的位置。它在图像里的位置会变。
- 不要为了够到面包片而转腰。转 `-0.3` rad 够不到所需深度，造成两次夹空，并让一个电机升到 `84 C`。

### 夹取、上拉与翻平（第 3 步）

- 用关节插值路点 `0.82 -> 0.805 -> 0.79` 下降。在可达边缘附近（`x = 0.55`），直线下降因分支翻转
  被拒绝。
- TCP 目标 `0.790` 是下限；实测 TCP 停在约 `0.795`。
- 开度 `0.13` 到 `0.20` 表示夹住，`0.02` 到 `0.06` 表示夹空。夹空后，张开夹爪，用腕部相机看图，
  修正偏移后再试。翻平路点上的 `"min_opening": 0.1` 能在夹空时让手留在烤面包机上方。
- 手退到 `x = 0.48` 时，上拉到 `0.92` 够不到；`0.91` 通过。那次上拉时，第一片面包片在出槽途中把烤面包机
  带转了约 `20` 度，所以下一次夹取之前要重新读剩下那片的位置。
- 竖直上拉到 `z = 0.92`。这是升降为 `0.522` 时的可达边界；`0.94` 被拒绝。只拉到 `0.885` 时，`12` 厘米
  面包片的下沿还在槽口高度，随后的搬运把烤面包机带倒了。
- 横向移动前先原地翻平：面包片会摆到 TCP 高度，手下方就没有东西垂着。在 `z = 0.92`，面包片还竖着
  时，任何朝身体方向的横向移动都不可达。
- 翻平姿态很敏感。2026-11-25 `[90, -10, -18]` 通过；前一天左槽用 `[90, -10, -8]` 通过，右槽用
  `[90, -10, -15]` 通过，`[90, -10, 0]` 被拒绝。要先预演。
- 从翻平姿态直接去松手前悬停点。不要经过 `(0.45, -0.15, 0.80)`：从右槽出发时，上臂到达那里时刚好
  低于 `20` 毫米 的自碰撞余量，此后服务拒绝所有运动，包括 `home`，操作员只能用手挪动肘部。
- 在预演里检查 `self_clearance_min_per_wp`。没有卡住的那条路线在每个路点都至少留有 `27` 毫米。
- 上拉之后，在头部视图里确认烤面包机没有移动。如果移动了，停下并告诉操作员。

### 放置与退出（第 3 步和第 4 步）

- 在松手前悬停点测量手里的面包片，松手前先修正 TCP。松手 TCP 与面包片中心之间的偏移取决于手指
  夹在面包片的哪个位置，所以没有固定偏移可用。有一次跳过这次看图，把面包片放到了超出盘子中心 `6` 厘米
  的位置，多花了 `253` 秒。
- 第一片的松手高度：`z = 0.68`。盘子在约 `(0.415, -0.02)` 时，`z = 0.66` 被拒绝（腕部在桌面上方
  `49` 毫米）。顶层面包片在 `z = 0.725` 松手。
- 松手 TCP 比约 `y = -0.05` 更靠近身体时被拒绝（自碰撞间隙 `18` 毫米）。在顶层面包片的悬停高度 `0.761`，
  搬运必须先经过 `(0.35, -0.065)`；直接去 `y = -0.04` 被拒绝（`19` 毫米）。
- 顶层面包片不一定会回滑。2026-11-26 第一片松在盘子上，手指滑出时向机器人方向移动了 `4.3` 厘米；顶层
  那片松在生菜上，留在夹持时的位置，最后比下面那片偏前 `3.5` 厘米。
- 下侧手指滑出时，面包片会朝机器人方向退回 `3.6` 到 `6` 厘米，而且这个量不可重复。顶层面包片在
  2026-11-24 最后偏了约 `4` 厘米，在 2026-11-25 偏了约 `2` 厘米。尚未试过：降低顶层面包片的松手高度，
  或在滑出前完全张开。
- 经 `(0.46, -0.12, 0.76)` rpy `[45, -5, 10]` 和 `(0.45, -0.15, 0.78)` rpy `[0, 0, 0]` 退出，然后
  `home right`。到达 `(0.45, -0.15, 0.78)` 之前执行 `home` 被拒绝。
- 参考叠层高度：盘面 `0.61`，第一片顶面约 `0.63`，生菜顶面约 `0.66`。用相机确认当前叠层。

## 生菜说明

- 第一片面包片放好后，把中间的盘子登记为障碍物，让规划器拒绝任何穿过它的路径：

```bash
curl -s --noproxy '*' -X POST http://127.0.0.1:8765/scene -d '{"obstacles":[{"name":"plate","center":[px,py],"size":[0.24,0.24],"top_z":0.66,"yaw":0.0,"margin_xy":0.02}]}'
```

  `top_z = 0.66` 时，`z = 0.70` 的生菜松手和 `z = 0.725` 的顶层面包片松手仍能通过。
  不要更早登记：`z = 0.68` 的第一片松手点在障碍盒内。
- 不要从 `home` 直接关节插值到叶子上方的悬停点。那一下摆动让张开的指尖扫过中间的盘子，把它推了约
  `4` 厘米。先原地上升，在 `z = 0.80` 走直线，再关节插值下降。从 `0.80` 直线下降因分支翻转被拒绝。
- 夹取 rpy：生菜小碟在 `(0.50, 0.20)` 附近时用 `[0, 35, -45]`。生菜小碟在约 `(0.51, 0.28)` 时，
  这个姿态够不到；`[0, 45, -37]` 通过。rpy 为 `[0, 15, ...]` 的平手姿态失败了两次。
- 夹取高度：目标 `z = 0.636` 到 `0.637`。目标 `0.6413` 时停在 `0.644`，在叶子上方合拢；`0.636` 时
  停在 `0.642`，夹住了叶子。
- 开度 `0.02` 到 `0.05` 可能表示夹住了叶子，`holding` 标志不可靠。腕部图像也不可靠：仍躺在生菜小碟
  里的叶子会显示在合拢的指尖旁边。上升之后，用头部相机确认生菜小碟已空。
- 搬运要高：实测路线在 `z = 0.76` 搬运。低位搬运曾把两个盘子都推了 `5` 厘米。
- 叶子落在哪里，松手 rpy 为 `[0, 5, -75]`；`(bx, by)` 是下层面包片的中心：

| 松手 TCP | 结果 |
|---|---|
| `(bx - 0.01, by + 0.067)` | 叶子盖住面包片的大部分 |
| `(bx - 0.01, by + 0.039)` | 叶子盖住右半边，并在 `-y` 边缘外垂出 `5` 厘米 |
| `(bx - 0.004, by + 0.029)` | 叶子只盖住右前半边 |
| `(bx - 0.01, by + 0.07)` | 叶子盖住右半边，并垂出 `-y` 边缘和近侧边缘 |

- 叶子相对手指朝 `-y` 垂出，垂出多少取决于手指夹在哪里，所以没有可靠的固定偏移。从
  `(bx - 0.01, by + 0.07)` 开始，再按悬停视图修正 `y`。
- 在悬停点不要把手沿 `x` 往回移。从指尖竖起来的叶子，投影位置比它落下后更靠前：2026-11-25 把手往回
  移了，结果叶子只盖住了面包片靠左、靠近侧的那一半。
- 最低的指尖在 TCP 下方；见 [EXPERIENCE.zh.md](EXPERIENCE.zh.md) 的“坐标系、TCP 与夹爪几何”。
  pitch 为 `35` 时，下垂量为 `2.97` 厘米。

## 推盘说明

只在用户要求时执行，并且要在三明治做完、双臂都在 `home` 之后。双手把盘子笔直向前（`+x`）推，就像
人用手的侧面把盘子在桌上推过去一样。

### 手的姿态

- 左手：rpy `[0, 15, -90]`，夹爪 `0.1`。手指横在身体前方指向 `-y`，开合轴沿 `+x`，所以前侧手指的
  外侧面是一个朝向盘子的竖直面。由这个面推盘沿。
- 手指朝前的姿态（`[0, 45..89, 0]`、`[0, 30, -30]`、`[0, 30, -60]` 及其右手镜像）在 `x = 0.22` 到
  `0.28` 对两只手臂都不可达。盘子离机器人这么近时，只有把手横过来才能够到后盘沿。
- 双手推盘时，右手用镜像姿态 `[0, 15, 90]`。只用一只手推时用左手：右手的镜像姿态 `[0, 20, 90]`
  可达，但它的前臂会朝烤面包机移动。
- 指尖是最低点：在 TCP 下方 `drop(15) = 0.0233*sin(15) + 0.020*cos(15) = 0.0253` m。
- 夹爪为 `0.1` 时，前侧手指的外侧面在 `x` 方向上比 TCP 靠前约 `0.03` m。

### 手放在哪里

设盘子最靠后的盘沿点为 `(rx, ry)`，从当前头部图像读取。

- `x`：TCP 从 `rx - 0.04` 开始，这样手指面和盘沿之间留有约 `1.2` 厘米。
- `y`：最靠后的盘沿点必须落在手指面上，从指尖往回约 `1.5` 厘米 处。平面推圆形盘沿时，推力经过盘子
  中心。如果指尖的角碰到盘沿上该点的一侧，盘子会被推向侧面，而且偏移会随着移动越来越大。
- 按图像对齐 `y`，不要按 TCP 数值。在 `x = 0.2` 附近，头部图像里的指尖比 TCP 位置推算的更偏向 `-y`
  约 `3` 厘米。实测那次运行中，TCP `y = 0.016` 时，指尖越过 `y = -0.017` 处的后点约 `1.5` 厘米。
- `z`：在 TCP `z = 0.624` 推。此时指尖在桌面（`0.595`）上方约 `8` 毫米，并低于盘沿。`z = 0.620`
  被拒绝（`left_wrist_yaw_link 49 mm above the table`）。

### 双手推盘（第 7 到 9 步）

- 先清除盘子的障碍盒（`POST /scene`，内容为 `{"obstacles":[]}`）。推盘的终点在障碍盒内，不清除就会
  被拒绝。
- 用 `both` 和 `"linear": false` 让双手一起下降，分 `0.76`、`0.70`、`0.66` 几步。先到 `z = 0.80` 时
  选中了抬肘分支（肩外展约 `110` 度），从那里直线下降被拒绝。
- 起始 `y`：两个指尖分别在盘子最靠后点的两侧约 `2` 厘米 处。2026-11-25 双手直接去了最终的 `y`
  （自碰撞间隙 `32` 毫米）。前一天这样做离线就被拒绝了（右手指和腰之间 `17` 毫米）；当时双手先悬停在
  `ry + 0.075` 和 `ry - 0.075`，再在 `z = 0.66` 用一次直线 `both` 运动移过去。由预演决定。
- 推盘终点：从 TCP `x = 0.188` 出发，`x = 0.40` 通过，`7.4` 秒 内把盘子推了约 `20` 厘米；`x = 0.41`
  因分支翻转被拒绝。
- 用 `both` 撤回：抬到 `z = 0.78`，直线到 `(0.45, +-0.15, 0.78)` rpy `[0, 0, 0]`，然后 `home both`。
  从抬起后的推盘姿态直接 `home both` 会被拒绝（两个指尖之间 `15` 毫米）。
- 盘子最后停在前臂 `home` 位置的下方。盘子上不能有比叠层更高的东西，生菜小碟和烤面包机必须在扫过的
  条带之外。

## 收尾与汇报

最后一次已授权的运动之后：

1. 用头部相机检查最终的三明治。
2. 运行 `bash r1d eef keyframe final`。
3. 运行 `bash r1d eef rec-stop`。
4. 确认运动安全且已获授权后，才用 `bash r1d eef home both` 让双臂复位。
5. 采集指标：

```bash
bash r1d metrics --run-dir runs/<run> --request "<user request>"
```

汇报实际完成的动作、最终图像结论、夹取开度、任何拒绝或人工修正、实测放置偏差、最高温度和指标路径。
缺少图像或温度采样时，说明缺失。不要因为命令被接受就推断放置成功。
