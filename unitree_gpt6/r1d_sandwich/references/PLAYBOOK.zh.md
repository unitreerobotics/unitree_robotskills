## 运行约束

- 手臂的每一次运动都是一个由服务的 IK 求解的末端路点。仅有的例外是关节空间 `home`、腰部命令和夹爪命令。
- `exec` 下发的每个路点都带 `auto_lift=False`，所以升降保持在服务启动时的高度。
- 整个任务全程录下头部、左腕和右腕三个视角。
- 位置用 R1-D 基座坐标系表示，单位为米：x 向前，y 向左，z 向上。参考桌面为 `z = 0.595`；
  盘面约为 `z = 0.61`。
- 每次摆放都不一样。物体位置要从当前图像读取。姿态、相对偏移和已经走通的路线形状，
  只有在核对过新场景之后才能复用。

路线见 [TASK_SANDWICH.zh.md](TASK_SANDWICH.zh.md)。制作三明治之前先读它。

## 命令与载荷

在 `SKILL.md` 所在目录执行命令：

```bash
bash r1d eef new
bash r1d eef prepare
bash r1d eef rec-start
bash r1d eef state
bash r1d eef look --cams head_left,left_wrist,right_wrist --raw
bash r1d eef look --cams head_left --z 0.61 --crop u0,v0,u1,v1 --scale 4 --mark "x,y,z;x,y,z"
bash r1d eef look --cams head_left --raw --crop u0,v0,u1,v1 --scale 4
bash r1d eef project --cams head_left --z 0.61 "u,v;u,v"
bash r1d eef check '<json>'
bash r1d eef exec '<json>'
bash r1d eef grip right grasp
bash r1d eef waist 0.0
bash r1d eef home right
bash r1d eef keyframe TAG
bash r1d eef rec-stop
```

`new` 在 `runs/` 下创建一个目录。之后的 `eef` 命令会追加写入这次运行的 `eef_log.jsonl`，图像放在
`looks/` 或 `keyframes/` 下。

标尺视图在指定平面上画出标定过的基座坐标系网格。线间距 10 厘米，点间距 5 厘米，红线上 x 不变，蓝线上 y
不变。`--mark` 把明确给出的基座坐标系点叠加到图上，这样可以对照图像核对估计值。

如果要量出位置，而不是对着网格估计，就读取像素并做投影：

1. `look --raw --crop u0,v0,u1,v1 --scale 4` 保存放大后的区域，每 10 px 一个刻度，
   刻度按整幅图像的像素坐标标注。
2. `project --cams head_left --z <height> "u,v;u,v"` 输出每个像素的射线与该高度水平面相交处的基座
   坐标系点。高度取像素所在表面的高度：盘子用 `0.61`，夹着的面包片的角点用这片面包片所在的高度。不带
   `--z` 时，头部相机使用双目深度。

每次 `look` 还会把各视角另存为 `runs/latest/<cam>.jpg`。会让机器人运动的命令（`exec`、`both`、
`grip`、`waist`、`home`）会先删掉这些文件，所以这个路径下的图片一定是最后一次动作之后拍的。
如果运动被拒绝、接在后面的 `look` 没有运行，那么文件是缺失的，而不是旧的。

路点载荷的格式如下：

```json
{
  "note": "slice 1",
  "segments": [
    {
      "side": "right",
      "speed": 0.15,
      "waypoints": [
        {
          "pos": [0.47, -0.15, 0.87],
          "rpy_deg": [0, 0, 0],
          "linear": true,
          "gripper": "grasp"
        }
      ]
    }
  ]
}
```

在 `note` 里写阶段名：`slice 1`、`lettuce`、`slice 2` 或 `push plate`。指标按这些名字划分运行。
`gripper` 字段可以是 `grasp`，也可以是 0 到 1 之间的数。

路点可以带 `"min_opening": 0.1`。运动到这个路点之前，`exec` 要求这只手的夹爪开度不小于该值，
否则就停在那里，输出 `NOT HELD`，退出状态为 1。它使用同一段里最后一次 `grasp` 报告的开度；
如果这一段没有夹取，就用实测开度。把它放在拉出之后的第一个路点上，这样夹取、拉出和搬运可以共用一条
`exec`，而夹空时仍然会停在烤面包机上方。只对面包使用：夹住的生菜叶读数为 `0.02` 到 `0.05`。

`check` 从当前位姿检查每个路点，不产生运动。被拒绝的路点返回 `ok=false` 和机器可读的 `code`。`exec`
在第一个被拒绝的路点停下，并以状态 1 退出。

对面包来说，夹取后开度为 `0.13` 到 `0.20` 表示夹住了，`0.02` 到 `0.06` 表示夹空。对薄的生菜来说，
开度和 `holding` 都无法给出明确判断；要从头部相机确认小盘已经空了。

## 离线预演与姿态

用与服务相同的 planner 预演候选序列：

```bash
bash r1d eval '{"side":"right","waist":0.0,"candidates":{"A":[{"pos":[0.47,-0.15,0.87],"rpy_deg":[0,0,0],"linear":false}],"B":[]}}'
```

输入可以带 `start_q`，包含全部 14 个手臂关节。否则使用机器人当前状态，因此服务必须在运行并且可读。
一次请求里放 5 到 8 个候选。在手拿起物体之前，就把放置方案和退出方案一起评估。

`bash r1d eval --brief '<json>'` 每个候选输出一行，给出用来在候选之间做取舍的数值：`OK`/`NO`、
最差外展角、最小肘部下沉量、最差肩偏航力矩、最大关节行程、最小自碰撞间隙（`selfmin`）、
最小桌面间隙（`gapmin`），失败时还有对应的路点和原因。完整输出里的 `link_gap_min_per_wp`
是桌面间隙；`self_clearance_min_per_wp` 是自碰撞间隙。

用 `eef both` 下发的双臂序列，用 `"side": "both"` 预演；这时每个路点有一个 `left` 位姿和一个 `right`
位姿。加上 `"end_at_start": true` 可以顺带检查沿关节空间回到起始关节角；如果手臂就是从 `home`
出发的，这一步就是回到原位：

```bash
bash r1d eval --brief '{"side":"both","end_at_start":true,"candidates":{"push":[{"left":{"pos":[0.509,0.149,0.80],"rpy_deg":[0,0,0]},"right":{"pos":[0.509,-0.149,0.80],"rpy_deg":[0,0,0]},"linear":false}]}}'
```

用以下命令读取手臂姿态：

```bash
bash r1d posture
```

姿态报告使用肩外展、肘部低于肩部的高度，以及肩偏航重力力矩的绝对值。在随包的辅助脚本里，
“ugly”正是由以下条件定义的：

- 肩外展大于 `45` 度；
- 肘部低于肩部的下沉量小于 `0`；
- 肩偏航力矩绝对值大于 `2.5` Nm。

这些阈值用于度量，不是命令限位。在路径其它方面都安全的前提下，选用外展更小、肘部更低、
肩偏航负载更小的候选。

烤面包机的障碍盒是场景安全模型的一部分。烤面包机挪动后，用 `look --mark` 重新画出并核对它的障碍盒，
并读取当前场景：

```bash
curl -s --noproxy '*' -X POST http://127.0.0.1:8765/scene -d '{}'
```

如果必须更新障碍盒，发送基座坐标系下的全部四个角点，或者等价的中心、尺寸、顶面高度和偏航角。
一个参考障碍盒是 `center=[x,y]`、`size=[0.26,0.15]`、`top_z=0.755`、`margin_xy=0.03`。
这些值描述的是参考烤面包机，不是新的摆放。

## 手臂姿态规则

- 每个阶段都从 `home` 开始。新路线在下发前先评估，选外展更小、肘部更低、肩偏航力矩更小的候选。
- 第一次真机运行里，用末端位姿作为“准备位置”，选中了另一个 IK 分支：肩外展 `48` 度，肘部朝外。
  右肩偏航电机因此承受约 `4` Nm，而标准姿态下是 `0.8` Nm，温度达到 `84 C`。
- 平放面包并松手时，从盘子右侧进入，rpy 用 `[90, -10, 20~30]`。这样肩外展约为 `5` 到 `10` 度，
  肘部在肩部下方 `3` 到 `13` 厘米。不要用 `[-90, 10, 75]`；它会把肘部抬到肩部以上。
- 在固定升降下，有些姿态没法做得自然。伸入烤面包机时外展约为 `80` 度。不要在它上方停留：保持得越久，
  姿态越差，关节也会发热。
- 夹取生菜和搬运菜叶时，左肘可能抬到肩高。第三次运行里，左臂在测量时间的 `91%`
  内都处于姿态不佳的状态。

## 安全

任何运动之前，先读 `state` 并确认：

- 模式是用户授权的那一个，并且 `stopped` 为 false；
- 两只手都在 `z = 0.70` 以上；
- 腰大约在 `0`；
- 本次运行已经执行过 `bash r1d eef prepare`：升降在 `0.522`，头部俯仰约为 `0.5`；
- 记录起始电机温度。

思考或离线评估时，不要让手臂一直保持受力的姿态。

服务会强制检查关节限位、自碰撞间隙、桌面上方间隙、已登记的障碍盒、单次运动位移，并执行看门狗停止。
它不知道盘子、食物、松散物体或人在哪里。从上方接近盘子，垂直下降，然后检查结果。

同一时间只能有一个控制方占用机器人。如果服务重启、日志目录变化，或者另一名操作员移动了手臂，
就停下并报告这一不一致。

## 效率

目标是每份三明治 30 分钟、40 次模型调用。第一次低于 40 次调用的运行是
`20261125-162207-real-eef-cc`：38 次调用、34.5 分钟、`$12.50`，包含双手推盘。这些时间的去向：

| 部分 | 时间 |
|---|---:|
| 机器人运动（全部 `exec`、`both`、`grip`、`home`） | 178 秒 |
| 一段既没有机器人命令也没有模型输出的空档 | 386 秒 |
| 其余全部：等待模型，每次调用约 40 秒 | 约 25 分钟 |

瓶颈不是手臂，而是模型调用次数。其中十三次调用什么也没做，只是打开上一条命令已经拍好的图片，
合计耗时 440 秒。

- **动作和看图放在同一轮。** 在一条 shell 命令里把 `exec ... && look ...` 接起来，并在同一轮里读取
  `runs/latest/<cam>.jpg`。工具按顺序运行，所以图片就是动作之后拍的那张；被拒绝之后文件是缺失的。
  不要专门花一轮只为打开一张图像。
- **每个决策一条 `exec`。** 两次看图之间的所有动作都放进一条 `exec`：悬停、放低，然后近距离看图；
  接着是下降、夹取、拉出、翻平，并搬运到松手前悬停点，`min_opening` 放在翻平的路点上；再接着是松手、
  滑出、退出。在最后一条后面接上 `home` 和 `keyframe`。
- **保留那些决定下一步的看图。** 它们是：合爪之前，放低并张开、停在面包片上方的手；
  松手前悬停点上夹着的面包片；悬停点上的菜叶；为推盘下降之前，位于盘沿后方的手指；以及每次放置之后的
  结果。有一次运行跳过了松手前的看图，代价是 `253` 秒。
- **在读图的那一轮里用 `project` 测量。** 从 `--raw --crop` 视图里读出像素并做投影；
  不要先对着网格估计，再多花一次看图去核对估计值。
- **每个阶段预演一次**，用 `eval --brief`，放置和退出一起预演，并根据结果写出整个阶段的路点。
  在手臂处于 `home` 时做，不要在它保持受力位姿时做。
- 复用已经走通的姿态和路线形状；只有物体位置变了才重新搜索。
- 数值反馈（TCP 位置、开度、拒绝代码）能回答问题时，优先用数值反馈。

现在的路线已经避开的早期代价：第三次运行里，烤面包机定位和第一片面包片花了 `19.8` 分钟、
`31` 次调用（头部视角看烤面包机不可靠；改用它上方的腕部视角）；夹第二片面包片时两次夹空，花了约
`6` 分钟（合爪之前，先从腕部相机检查放低并张开的夹爪）；一次运行里有七个放置或退出路点被拒绝（把它们
放在一起预演）。

## 运行结束后

1. 保存 `final` 关键帧并运行 `rec-stop`。
2. 把指标采集到运行目录：

```bash
bash r1d metrics --run-dir runs/<run> --request "<user request>"
```

指标的统计范围是从第一条到最后一条 EEF 指令，前后各加一分钟。如果自动查找会话记录时无法确定是
哪一份，就传入 `--transcript`。采集器报告墙钟时间、模型调用、成本、各阶段尝试次数、
已下发和已执行的路点、夹取开度和电机温度。

复盘结果时，为这次运行写一份 `annotations.json`。记录每个阶段的尝试次数、是否成功、夹取开度、
放置偏差、是否碰到盘子以及值得注意的事件。只报告观察到的事实，缺少的图像或传感器采样要明确指出。
