# Board Position Marking Task for a New Model

English | [中文](mark_board.zh.md)

Goal: based on the original head-camera board image that the user currently provides or that this round's workflow obtains, mark the 90 board-surface intersections of the Chinese chess (Xiangqi) board and output a traceable annotated image, pixel table and review notes. First read the parent README and the script's `--help`; obtain every value from this image. If there is no actual image, state that input is missing and do not fabricate marking results; this task does not require starting the robot or moving the arms.

1. **Fix the input.** Use the current `cam_left_high` original image and record its path, dimensions and SHA256. Avoid screenshot scaling, mirroring or cropping; if the image must be processed, treat the processed image as a new, explicit input and never mix pixel coordinates.
2. **Confirm the board orientation.** From the robot's viewpoint, a–i run left to right and 0–9 run near to far; a0 is the near-left intersection and i9 the far-right intersection. First check the four corners, the river and the palaces; do not guess the orientation from piece occupancy. The standard script requires a→i to point right and 0→9 to point up in the image; for a non-standard view, first establish the orientation explicitly and produce a canonical image. Which side is Red or Black is not something this tool infers.
3. **Read the real visible grid lines.** Look at the whole image, then zoom in near each intersection to confirm that two printed lines cross. Zoomed images are for reading lines; values must be converted back to original-image pixels. Never use piece centres, the gripper, shadows or piece edges in place of board-surface intersections. Points occluded by pieces are not listed as measured, and fitted predictions must not be used to fill in control points.
4. **Organise the control points.** Run `init` to generate the blank JSON and confirm the orientation. Fill in well-distributed `fit` points and keep separate `holdout` points that do not take part in fitting. At least 6+2 per region; include edges and interior as far as possible. Write the reading basis into note; coordinate precision should match what is discernible in the original image, and do not claim sub-pixel measured precision with long decimals.
5. **Fit and diagnose.** Start with `global`; explicitly specify the pixel residual threshold based on the reading precision of this image. Check per-point residuals and rule out mislabelled square names, mixed dimensions, shadows and top-surface parallax. Switch to `split` when necessary, with each region providing enough control points; do not hide wrongly read points by splitting or relaxing the threshold. Collinearity, too few points, a changed image hash, out-of-bounds projection or a reversed orientation must have their cause resolved first.
6. **Visual acceptance.** Open the generated PNG and check that all 90 points are unique, every rank and file is in the correct order, the four corners and both sides of the river fit, and the interior does not drift. In particular check the visible intersections near this round's source/target, occluded extension lines and adjacent squares. Distinguish observed from inferred points; a small residual does not mean the pixel mapping is reliable in occluded areas, let alone that it reflects arm accuracy. When something cannot be seen clearly, state the gap explicitly.
7. **Deliver.** Write `visual_review.md` in this run, noting the input hash, control/holdout point counts, the reason for the model choice, residuals, the visual conclusion and unverified regions; list the JSON/CSV/PNG paths. If the numerical checks pass but vision is not confirmed, keep it pending review and do not claim success. The query command only returns board-surface pixels and does not establish arm coordinates.
8. **Use for moves.** The actual centre of a piece in the original image and the target intersection must be observed separately; a piece may be off the square centre and its top surface has parallax. The head image cannot directly locate intersections in the wrist image or output base ΔX/ΔY. Estimate the robot poses for the actual source/target separately according to this round's procedure; if end-effector calibration is still missing, record that explicitly and do not fill it in from historical examples.

Before delivering, confirm again: no old board coordinates were read as marks for the new image, no inference was described as a measurement, no piece top surface was treated as the board surface, no pixel error was treated as millimetre error, and no robot motion was triggered.
