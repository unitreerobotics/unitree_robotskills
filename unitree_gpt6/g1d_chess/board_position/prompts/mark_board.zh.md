# 给新模型的棋盘点位标记任务

[English](mark_board.md) | 中文

目标：基于用户当前提供或本轮工作流取得的头部棋盘原图，标出中国象棋90个板面交点，输出可追溯的标注图、像素表和复核说明。先读上级README与脚本`--help`，所有数值从本次图像获得。没有实际图片时说明缺少输入，不伪造标记结果；本任务不要求启动机器人或移动手臂。

1. **固定输入。** 使用当前`cam_left_high`原图，记录路径、尺寸和SHA256。避免截图缩放、镜像或裁剪；如果必须处理图片，把处理后的图作为新的明确输入，不能混用像素坐标。
2. **确认棋盘方向。** a–i按机器人视角从左到右，0–9从近到远，a0为左近交点，i9为右远交点。先核对四角、河界及九宫，不用棋子占位猜方向。标准脚本要求图中a→i向右、0→9向上；非标准视角应先明确方向并生成规范图。红黑方归属不是本工具推断的内容。
3. **读取真实可见格线。** 查看全图，再放大交点附近确认两条印刷线相交。放大图用于读线，填值要换回原图像素。禁止以棋子中心、夹爪、影子或棋子边缘替代板面交点。棋子遮挡的点不列为实测，不靠拟合预测值补控制点。
4. **组织控制点。** 运行`init`生成空白JSON，确认方向。填写分布充分的`fit`点，另留未参与拟合的`holdout`点。每区至少6+2；尽量包含边缘和内部。读点依据写入note，坐标精度应符合原图可辨程度，不用长小数宣称亚像素实测精度。
5. **拟合与诊断。** 先`global`；根据本次图像读点精度明确指定像素残差阈值。检查逐点残差，排除格名标错、尺寸混用、阴影和顶面视差。必要时改`split`，两区各自提供足够控制点；不靠分区或放宽阈值掩盖错误读点。共线、点不足、图像哈希改变、投影出界或方向颠倒应先解决原因。
6. **视觉验收。** 打开生成PNG，检查90点唯一、各排各列顺序正确、四角和河两侧贴合、内部不漂移。尤其核对本轮source/target附近可见交点、遮挡延长线及相邻格。区分观测与推算；残差小也不代表像素映射在遮挡区可靠，更不代表机械臂精度。看不清时明确说明缺口。
7. **交付。** 在本次run写`visual_review.md`，注明输入哈希、控制点/留出数量、模型选择理由、残差、视觉结论、未验证区域；列出JSON/CSV/PNG路径。数值检查通过但视觉未确认时保持待复核，不宣称成功。查询命令只返回板面像素，不建立机械臂坐标。
8. **用于走棋。** 原图中棋子的实际中心与目标交点需分别观察；棋子可能偏离格心且顶面有视差。头图不能直接定位腕图交点或输出基座ΔX/ΔY。实际source/target的机器人位姿另按本轮流程估计，末端标定尚缺时明确记录，不从历史例子补入。

交付前再确认：没有读取旧盘坐标作为新图标记，没有把推算说成实测，没有把棋子顶面当板面，没有将像素误差当毫米误差，也没有触发机器人动作。
