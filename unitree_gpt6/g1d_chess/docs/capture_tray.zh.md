# 吃子移除：执行手同侧圆盘

[English](capture_tray.md) | 中文

棋盘两侧圆盘作为被吃子的存放target；物理左手执行移除就放左侧圆盘，物理右手就放右侧圆盘。侧别按机器人自身左右判断，不按相机流名或逻辑`right_arm`字段判断。己方棋子的target仍为原吃子目标交点。

规划时使用本轮头图定位同侧圆盘，在盘内可用区域选落点，避开盘沿和已存放棋子。XY基于本轮图像及工具姿态估计，左右手圆盘释放高度统一固定为机器人基座坐标Z=0.159m，不复用旧棋盘target或任意桌面点；不要求落在圆盘中心。盘内没有可用区域时不能自行改放另一侧或盘外。

在`capture.offboard_target`填写：

- `kind: "round_tray"`；
- `physical_side: "left"`或`"right"`，与本轮物理执行手一致；
- `xy_m`、固定`z_m: 0.159`、`rpy_rad`和本轮图像`evidence`；
- `capture.offboard_surface_review`记录盘内可用区域、盘沿/已有棋子、承托高度、工具净空与回撤路径。

模板预填圆盘`z_m=0.159`，XY按本轮图像填写；左右手均采用此释放高度。规划器拒绝非圆盘、侧别不匹配或释放Z不为0.159m的移除目标，将圆盘位姿及依据记入`plan_summary.capture_target`。这项校验核对填写的语义与侧别，不代替图像定位和完整服务预检。

吃子提前联合准备两个事务并只执行一次sequence：先把被吃子移入同侧圆盘；释放开爪到位后，立即按预检路径竖直上撤、经净空staging到己方棋子source高位复拍。staging只作运动路径点，不等待人工操作、另一次拍照或服务请求；第二段沿用张开的夹爪，不重复开爪。己方棋子放到目标交点后才回init。开爪未到位或运动保护拒绝时停止衔接。此规则对左右手和任意被吃子相同，sequence全程由同一物理手执行。

圆盘释放前先下降至计划Z=0.159m再复拍，以执行手腕图为主、头图辅助。预计棋子整体落入同侧盘内可用区域、避开盘沿和已有棋子即可释放；不要求精准居中，不套棋盘交点判据。盘外、压盘沿、干涉已有棋子、真正无法判断落点或有碰撞风险按需要修正处理。棋子遮住盘内目标点本身不算看不清。使用有依据的非零低位XY修正，保持实际Z/RPY；无单次或累计距离上限，不进行修正段运动检查。最多3次，前两次后复拍，第三次后直接原位张爪，不追加复拍或审批条件；实际硬件或控制故障仍按原流程处理。

本包规划器为移除事务生成`alignment_criterion=actor_wrist_predicted_landing_inside_same_side_tray`，预检须返回同一判据；计划与预检回执的圆盘判据必须一致。实际执行只用本次部署包根的规划器、服务和新token。磁盘更新不自动加载到现有进程；版本及修正策略实现边界见[runtime](runtime.zh.md)。新设备先按[首次配置](first_game_setup.zh.md)核对圆盘与固定高度的兼容性。
