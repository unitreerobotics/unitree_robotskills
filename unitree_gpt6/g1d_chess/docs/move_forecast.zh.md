# 每轮决策的五轮预测

[English](move_forecast.md) | 中文

预测命中的着法可横跨棋盘，不按“对侧最外两列”过滤。按[选招与机器人可达性](move_constraints.zh.md)先预检首选手，不可达再预检另一手；两手均不可达才舍弃该候选并重搜。

适用当前红方机器人、黑方对手流程。每次必要搜索后保留选定主变，从当前红方回合开始按`红1、黑1、红2、黑2、…、红5、黑5`排列，最多10个半回合。提前终局或有效主变较短时按实际长度保存，不补造着法。引擎优先寻找更短的正mate胜线；未搜索到强制胜线时保存最佳可用主变及实际评分，不宣称保证最快获胜。

## 每轮规划顺序

1. 采本轮唯一一张规划用left_high，结合上一轮复盘确认红方上一步实际落格，再识别黑方实际着法与当前棋局。
2. 读取本局预测，从已确认进度向前核对：上一红方着法成功、黑方source/target及吃子与预期一致，当前棋子布局、行棋方和实际走子历史也一致。
3. 一致且尚有下一步红方着法：经规则库核验合法后，将其作为候选，不因横跨棋盘而重搜，也不每轮补满预测。按本轮新图估计抓放坐标，先完整预检首选手，不可达再试另一手；两手均不可达才舍弃并重搜。
4. 无预测、黑方走法不一致、剩余预测没有下一步红方着法或当前候选经两手完整预检均不可达：从当前真实局面重新搜索并保存新五轮预测。复位、新局、己方落错格、预测文件损坏、着法不合法或局面不一致均使旧预测失效。实际局面不明时先识别，不从旧预测推断实物状态。
5. 在execute前保存本轮选择及预测。发出运动请求不代表该着法已完成；下一轮规划时根据已有复盘与新图确认进度。旧客户端超时或同轮重新规划时也按真实结果判断，不能重复消费预测或重复走子。

选定着法及source执行手之后、估计source/target之前，按[历史 ΔXYZ 误差参考](xy_error_learning.zh.md)从本轮`<本轮run>/docs/execution_xy_errors.jsonl`读取该物理手在当前兼容context下的历史累计 ΔXYZ 均值。预测命中不省略误差参考；source和target分别看抓取/低位释放的历史位移误差均值；XYZ仍基于本轮图像估计，均值只作辅助参考，不平均实际抓放坐标，不直接叠加误差、不改坐标表。复盘第2项的finish负责追加本轮误差及左右手累计，不在规划阶段提前计入待执行着法。

例如已保存`红1→黑1→红2→黑2…`：红1实际成功、黑方实际走黑1，则直接走红2；黑方走了其他着法，则从新局面搜索。仅剩红5时可直接走红5；下次红方回合无剩余着法才重新搜索。当前局面已经终局则结束走棋，不因预测耗尽而继续搜索动作。

## 保存位置与内容

上一轮最终复盘位于其run的`docs/{第几轮}_{这一轮的走棋子方案}_{时间戳}.json`；按[操作手册第8节](operation_manual.zh.md#8-走棋完成后的复盘仅两项)核对内容中的本局归属、轮次、着法和真实结果。轮次是本局我方行棋计数，不随预测重新搜索而重置。

同一棋局使用本次部署包根下`runs/<本局目录>/move_forecast.json`作为当前预测入口。新局使用新目录，并根据本局标识与当前实际棋局确认归属。每次规划在本轮`tmp/move_forecast.json`保留快照，便于下轮定位来源；两者均在规划阶段保存。不同run沿用同一本局入口，不在执行后复盘新增索引维护。

预测记录至少包含：

- `game_id`、生成时间、来源run、引擎参数/原始评分及日志路径。
- `base_fen`、搜索起点之前的实际走子历史；逐步按规则推演，不仅比较source/target两个格。
- `rounds`：最多5组，分别保存红方和黑方着法；每步记录执子方、引擎UCI、手册source/target、吃子信息、`fen_before`、`fen_after`。主变提前结束时缺失应手为null，并说明终局或主变不足。
- `confirmed_ply_count`：只统计已由真实观测/上轮复盘确认的半回合；预测局面与实物局面分开存。
- `selected_move`及`selected_ply_index`：本轮待执行红方着法，标为待确认；`decision_source`为`forecast_match`或`engine_search`，重新搜索时记录原因。

比较FEN时由规则历史构造计数信息；图片只提供可见布局，不把图像不可见的计数当成视觉测量。若缓存与真实局面无法一致对应，废弃该预测，从已确认局面重新搜索。

## 与执行、复盘的边界

复用的是棋规着法，不是旧机械臂坐标、轨迹或token。每轮仍只按source选手，并使用当前实测起点、当前图像、独立source/target估计及完整预检。若当前着法无法执行，不以预测命中为由绕过检查；需改选着法时在规划阶段作废旧预测并搜索。

**execute期间只处理当前检查点，立即复拍、立即决策、立即提交；不调用引擎或维护预测。** 走棋结束后仍只做新left_high成功/偏位判断及FK误差计算合并落盘。预测确认进度推迟到下一轮规划，不增加第三项复盘。

搜索前可用`scripts/move_constraints.py`将全部棋规合法着法生成`searchmoves`，并核验返回的bestmove。当前脚本不按横跨幅度过滤候选，未来主变也不据此截断；对手应手仍按棋规原样保留。无合法着法时不发送无约束搜索命令。走棋前的实际可达性以本轮两手完整预检为准。预测缓存读写由主会话在规划阶段完成，当前没有自动维护缓存的通用CLI。
