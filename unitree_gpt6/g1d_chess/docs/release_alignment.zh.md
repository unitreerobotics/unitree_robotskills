# 释放前预计落点与目标交点判定

[English](release_alignment.md) | 中文

在下降至释放高度、尚未张爪时复拍，以物理执行手腕部相机判断棋子预计落点，头部图辅助核对目标格名与邻子。预计落点应在对应交点附近，允许小幅偏心，不要求完全精准对齐；同时核对整枚棋子下落不与邻子重叠，以及张爪、竖直上撤无明显干涉。邻子关系见[邻子间隙与准确落子](neighbor_clearance_and_landing.zh.md)。

| 执行手腕图支持的预计落点 | 决策 |
| --- | --- |
| 相邻两个交点之间 | `adjust`，向目标交点修正 |
| 方格中间 | `adjust`，向目标交点修正 |
| 明显错开对应目标交点，包括靠近错误交点 | `adjust`，向对应目标交点修正 |
| 对应目标交点附近，仅小幅偏心且可安全释放 | `success`，原位张爪 |
| 棋子覆盖目标交点，但可结合可见格线及棋子中心判断落点 | 不属于看不清；按预计落点是否接近目标交点决策，不因遮挡本身修正 |
| 真正无法判断预计落点，或存在碰撞风险 | 按需要修正处理，`adjust`；说明不确定处或风险及修正依据 |

判断的是棋子张爪后的预计落点，须结合夹持偏心、棋子顶面与板面视差、棋子和目标格线关系。夹爪外壳、影子、棋子边缘覆盖交点，以及末端FK误差小，都不能单独证明落点对准。未标定时不硬设毫米/像素阈值。`reason`及`evidence`写明本次执行手腕图路径、预计落点与目标交点关系和修正偏向。

棋子覆盖目标位置交点本身不属于看不清，不要求交点完整露出。通过可见格线延伸、邻近交点、棋子中心及视差推断预计落点；覆盖交点本身也不能单独证明对准。只有这些信息仍不足以判断落点时才属于真正看不清。

提交格式为七字段，`obvious_large_offset`用于区分是否需要修正：上述需要修正的明显偏差、真正无法判断预计落点或碰撞风险均为true，`release_alignment_verified=false`；交点附近可释放的小幅偏心为false。`release_alignment_verified=true`表示已核对预计落点在对应目标交点附近且可安全释放，不表示精确居中。需要修正的分类不等于任意位移许可：提交adjust仍须识别目标、给出有依据的非零XY，不能虚构目标识别或修正位移。XY修正不设单次或相对原计划目标的累计距离上限，不进行修正段运动检查，最多3次。图像语义判断由主会话完成；操作规范与运行实现的差异见[runtime](runtime.zh.md#实现核对边界)。

本包规划器生成的计划和服务预检需匹配`adjustment_policy=obvious_off_target_intersection`及`alignment_criterion=actor_wrist_predicted_landing_near_target_intersection`。计划与预检回执的策略字段必须一致。吃子移除使用`alignment_criterion=actor_wrist_predicted_landing_inside_same_side_tray`：左手放棋盘左侧圆盘、右手放右侧圆盘，左右手圆盘释放高度均为Z=0.159m。预计棋子整体落入盘内可用区域、避开盘沿和已放棋子即可释放，不要求圆盘中心精准对齐；盘外、压盘沿、干涉已有棋子或真正无法判断落点则需修正。棋子遮住盘内目标点本身不算看不清。详见[圆盘吃子规则](capture_tray.zh.md)；上述交点规则用于己方落子。

动作顺序为target高位、下降、保持夹持复拍、决策、张爪。修正相对本次低位实际FK，保持实际Z/RPY直接XY调整，不抬升；最多3次，前两次后复拍，第三次修正完成后直接放行原位张爪，不再追加复拍或视觉审批；不进行修正段运动检查，实际硬件或控制故障仍按原流程处理。完整流程见[操作手册 0.5.2](operation_manual.zh.md)及[每轮plan第4步](../prompts/round_plan.zh.md)。

服务进程不会自动加载磁盘修改。授权执行前核对本包ROOT、进程版本、当前状态和新token；需要更新进程时按README在空闲、空爪等条件下有序处理。修正策略与现有代码的差异见[runtime](runtime.zh.md)，不能仅凭文档宣称实现已改变。
