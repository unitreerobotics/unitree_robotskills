# R1-7a 马克笔整理（真机）

[English](SKILL.md) | 中文

文中数值都是真机实测，是起点不是定律；换了笔、笔盒或桌面要重新确认。准备工作（关节控制接口、IK、相机标定）和工具说明见 [README.zh.md](README.zh.md)。

两份补充文档，遇到对应情况再读：

- 桌面是白色的：笔身和桌面同色，找笔、定盒、垂直检查都有不同做法，开始前读[白色桌面说明](docs/white_desk.zh.md)。
- 要改检测、路径、抓取或下放参数，排查失败，或想知道某个做法为什么这样定：读[控制与感知要点](docs/perception_and_control.zh.md)。

## 开始前

- 三样准备好了才开始（见 README“开始前的准备”）：用户自己的关节控制已接到 `src/robot/rt.py` 的 `state`、`move`、`gripper` 和 `src/robot/grab.py` 的 `frame`；IK 用 `src/ik/kinematics.py` 加 R1-7a 的 URDF；相机已用 `src/calibration/` 标定，`src/calib.json` 存在。
- 桌面可以深色，也可以是白色桌面；笔可以任意摆放，抓法见流程第 3 步。
- 机械臂由用户自己的控制程序使能并保持；不要启动、重启它。读 `state()`：`armed=true`、`fault=null`、夹爪已标定，相机 1280×720。
- 运动脚本只在前台分步跑。杀掉脚本不会停下已下发的轨迹，也可能停在“正夹着笔”的中间状态；中断后先读夹爪状态再决定下一步。
- 路径检查必须用 `assert` 拦截，不能只打印结果后照走。一步断言失败后，下一步是从“半路”的姿态出发的，先看清手在哪里。
- 连着跑的步骤，任何一步失败都必须让整串停下；中间的检查结果看过再往下。

## 示例盒子和笔（实测）

- 笔长 153–155 mm。一端是**方形大笔帽**（离端面约 30 mm 处有一圈深色分界线），另一端是细头。大帽朝上入盒，所以**始终抓大帽端**。两端的笔帽都印着色号，认大帽端只看分界线。
- 槽距 17.5–17.8 mm，笔帽顶面高出桌面 150–151 mm，笔立在盒底。
- 盒内约 65–70 mm 深处（笔帽顶面以下）有一层**方孔格栅**。细头要先进孔（容差约 ±3 mm），方形笔身还要转正才能落到底。卡住的高度能说明原因：

| 笔帽比邻笔高出 | 状态 | 处理 |
| --- | --- | --- |
| 约 85–90 mm | 细头顶在格栅上，没进孔 | `reseat` |
| 约 55–59 mm | 细头进孔，笔身没转正 | `reseat`（保持当前高度夹住） |
| 0 | 到底 | 完成 |

- 色号只能在抓起后从腕部图里读（大帽正对相机）。盒内排列以当场看到的邻号为准，不套用固定表格。

## 流程（每步之间看图）

工具都在 `src/` 下以 `python3 -m <目录>.<脚本>` 运行，每一步是 `python3 -m sorting.sort RUN <步骤>`；`RUN` 是这一轮的目录。

1. **定盒，每轮都做，碰过盒子也要重做。** 2–3 个俯视姿态（`perception.view_plan`，盒子大致没动就复用上一轮的姿态），`perception.box` 用彩色笔帽多视角拟合槽格，初值用上一次的结果；盒子转动超过 ±45° 或平移超过 4 cm 时要先给新的初值。**必须打开叠加图** `*_box.jpg` **看圆圈是否都落在笔帽上**，并核对笔帽高度 150±2 mm、槽距约 17.8 mm：重投影残差说明不了问题，错了半格或一整格时残差照样只有 1.6 px。空槽也在这张图上确认。俯视姿态要接近正上方，而且 24 个槽都不被手指挡住；三个视角的叠加图都要看，只看一张会漏掉歪的那张。拟合时笔帽高度固定为 150.5 mm、槽距带 17.85 mm 的先验：两者放开时，斜着拍的图会把槽距拉到 17.4 mm，远端几排偏 5–8 mm，笔会被放到邻笔的笔帽上。重摆场景、碰到盒子都会让它挪动几毫米到 1 cm；用户说碰到了就一定重做。

2. `look`**。** 高位总览，找出桌面的笔和大帽端（靠分界线判断，不靠粗细）。被手指挡住的笔换个 J1 角度看（`look 0.45`）；被挡住一截时长度会偏短，但大帽端位置仍可用。检出数和肉眼数不一致时先修检测再动手（压着纸屑的笔可能被漏掉）。交叉或相碰的笔会被拆成各自的轴线并标出 `CROSSES`；有一支笔伸到手指后面时换个角度（`look 0.3`）让每支笔都完整入画。**多支笔堆在一起时**，放大图像，用 `addpen` 手工标出没自动认出的笔（深色笔帽、交叉的笔），大帽端按分界线定。

3. `pick K`**，抓大帽端。** 竖直向下夹在离大帽端面 1–3 cm 处，**相机一侧朝大帽**，小步抬起，翻到携带姿态（夹爪水平、笔下垂、大帽正对相机），读色号。要点：

   - **夹紧。** 夹爪是位置环，夹紧力矩约等于 26 Nm ×（被笔挡住的开度 − 闭合指令）。指令 0.13 只有 0.7 Nm，笔抬起后会在指间转歪；用 **0.08**（1.5–1.9 Nm）。笔歪了先怀疑没夹紧，不是碰到了东西。
   - **按算出的高度下压，手指贴到桌面就停，直接闭合。** 算出的指尖高度随手臂姿态能差 8 mm：偏高会夹在笔的上方（空夹），硬要压到“算出的 4 mm”又会把桌面顶住。做法是朝目标高度修正，跟踪误差一开始增大就停；贴着桌面闭合没有问题。
   - 抓取方案全程离关节限位 0.10 rad 以上。用 `sorting.pick_direct RUN K [--wide]`，它按下表自动选抓法；`--dry` 只出方案不动手。报无解时先离线分段查（逆解 / 间隙 / 路径 / 下降 / 抬起 / 到携带位），看死在哪一段。

   按笔的摆法选抓法：

| 笔的摆法 | 抓法 |
| --- | --- |
| 横着或斜着躺 | 标准抓法：竖直向下，夹爪垂直于笔身 |
| 正对或背对机器人、离底座远 | 夹爪绕竖直方向转 ±10–30°，抓取点挪到离大帽端 30–45 mm，原地直接抓（笔会被手指带正）；周围没有别的笔时可转到 ±60°（`--wide`） |
| 紧挨着盒子 | 抓起后先横移离开盒子再翻转，否则翻转时笔尾会扫到盒子 |
| 和别的笔交叉、相碰或叠放 | 见第 4 步 |
| 以上都无解（太远、贴着关节限位） | 转存，见第 5 步 |

| 情况 | 闭合指令 | 开度反馈 | 力矩 |
| --- | --- | --- | --- |
| 夹住笔帽（抓取） | 0.08 | 0.144–0.150 | −1.5 \~ −1.9 |
| 夹住笔帽（`reseat` 用，轻握） | 0.13 | 0.155–0.159 | −0.65 \~ −0.77 |
| 夹住笔身中段（转存） | 0.13 | 0.175 | −1.2 |
| 空夹 | 0.08 / 0.13 | 0.089 / 0.137 | −0.26 / −0.20 |

“是否夹着”的判断阈值跟着闭合指令走；改了指令没改判断，会把夹着的笔报成丢了。

4. **笔叠在一起时不用分上下。** 抓哪支都行，只要抓取点离交叉点 4 cm 以上、张开的手指不落在另一支笔上（`pick`、`restage` 会检查并拒绝）。先拿大帽端离交叉点远的那支；拿走下面那支时，上面的会自己滑到桌面上。**每拿走一支都重新** `look`，并重新标注：拿走一支常常会把旁边的笔带动，有时带到 40 cm 外、够不着的地方。先拿认得出、大帽端周围空的那支，桌面变简单后再认剩下的。分界线正好压在交叉处的那支笔，大帽端会报“未知”，先拿别的。不用判断谁在上面。

5. **直接抓和转角度抓都无解时，**`restage K` **转存。** 先夹笔身中段，把笔平放到 (0.06, −0.20)、沿 x、大帽在 −x 一侧，再 `look`、`pick`。转存位上已经躺着别的笔时，先处理那支。夹中段时笔两端各伸出 7.5 cm，转存的路径检查包含了笔对盒子的避让。

6. **笔在指间摆歪了就放下重来。** 携带姿态下 `pick` 会检查笔是否垂直下垂；不垂直就 `putdown X Y DX DY` 放回空处重抓。歪笔绝不往盒里放。主要原因是夹紧力不够（见第 3 步），其次才是笔尾碰到东西。

7. `place I J`**。** 笔在指间的实际位置和标称不一样时（笔帽在腕部图里偏低），按实际位置设 `GRASP_D` 再下放。下放构型要在很多个逆解里找（前几个扭转小的常常半路撞上 J6 限位）。夹爪朝向与槽格对齐，笔尖在高于笔帽时闭环对位，下放到被格栅顶起超过 5 mm 或手指接近笔帽为止，松爪，退出。

8. `verify`**。** 俯视图确认笔帽与邻笔齐平、槽位正确。正着放的笔大约三分之一直接穿过格栅孔到底，三分之一顶在格栅上、松爪后落到底，三分之一松爪后斜立（需要 `reseat`）。斜立是常态，不是意外，时间要按“每支笔可能多一次补救”来算。

9. **斜立就** `sorting.reseat2 RUN I J`**。** 两个视角三角定位这支笔的笔帽（两条视线相差超过 4 mm 就是认错了，不要用）→ 夹爪下俯 25°、朝向与槽格对齐、笔在指内 15 mm 处**夹紧**笔帽 → 把笔摆正到槽心正上方、笔尖略高于格栅（夹持点 = 邻笔帽顶面 + 79 mm）→ **松到开度 0.21** 成笼（每侧约 2 mm 间隙）→ ±2/4/6 mm 小圈加 ±8° 偏航晃动，笔靠自重落下。第一条视线取自验证图，第二个视角自动挑一个又近又陡、笔帽不被手指挡住的位置。正着放的笔基本一次就进。深色笔帽（如紫色）在两张图里手工取点（`sorting.reseat2 … px U V` 加 `sorting.reseat_marked`）。是否落下以俯视图为准。然后再 `verify`，并重新定盒。

   **同一支笔补救两次、现象一样，就停下来换个原因想**（槽位对吗？夹的是大帽端吗？），不要换着花样再试。

## 汇报

每轮的图片、拟合结果和日志都在 `RUN` 目录里。汇报目标数、俯视图确认归位的数目、每支笔的槽位和证据图、失败与恢复、耗时。未经俯视图确认的不算成功；范围被缩小要写明，不改分母。
