# 机器人执行安全

[English](safety.md) | 中文

## 当前支持边界

导航的统一预览 CLI 入口只有本地无动作预览，不是物理仿真。该入口没有连接检查、逆运动学、避障、接触力控制或急停实现。`--mode hardware` 和非 `preview` 配置会被拒绝。配置中的机器人型号只验证声明一致性，不能确认实际设备。

例外：`g1d_r1d_navigation/src/navi_agent/` 是独立的真机运行时，会驱动底盘运动。它有雷达反射层限速、指令看门狗和软件停止，但都不能替代硬件急停；使用前阅读该技能 README 的安全分层与现场检查清单。

中国象棋包含真实机器人 SDK 接口、逆运动学、服务与执行脚本，须按其 [SKILL.zh.md](../unitree_gpt6/g1d_chess/SKILL.zh.md) 和 [运行说明](../unitree_gpt6/g1d_chess/docs/runtime.zh.md) 核对配置与能力边界。上述预览模式限制不适用于象棋入口。

所有模型输出和计划都应作为待验证输入。真机接口接入必须独立设计，不能仅删除模式检查就开始执行。

绘画提供 G1-D / Dex1 硬件后端、连接与反馈检查、URDF / IK 编译、执行停止和控制权管理。编译与运行仍需要匹配实际设备的模型、工具和现场测量。

绘画当前保留反馈过期、发布失败、控制模式变化、持续跟随异常、接触点到位、最低抬离高度和离线关节限位等检查；悬空目标位置、朝向及最终休息位的关节偏差记录到日志，不作为严格到位门槛。程序停止不等于现场硬件急停，当前没有自动碰撞检测、接触力闭环或温度 / 电流阈值保护。

五子棋包含相机、SDK、FK/IK 与持续控制工具，必须先核对私有配置、标定、发布器健康和动作证据。松爪须记录明确用户确认，释放后连续回撤并验证归位；模型不得绕过这些条件。接口与已知边界见 [自主轮次说明](../unitree_gpt6/g1d_gomoku/docs/autonomous_play.zh.md) 和 [硬件接入](../unitree_gpt6/g1d_gomoku/docs/hardware_integration.zh.md)。

## 硬件接入前的要求

1. 核对机器人型号、SDK/固件、连接、控制权与设备状态。
2. 标定相机、末端、棋盘、绘画平面或导航地图；明确坐标系和单位。
3. 对位置、关节、速度、加速度、接触力与工作空间设置明确边界。
4. 规划后、每次执行前再次验证动作；模型不能绕过适配器的约束。
5. 设置任务与单步超时、独立执行看门狗及通信中断处理。
6. 提供任务取消、停止与进入安全状态的机制，并先验证现场急停可用。
7. 先做无动作检查和适当的仿真，再在隔离区域、人员监护下逐步进行真机验证。

这些是硬件接入的验收要求；各技能已实现的能力、差异与限制以对应运行说明为准，离线验证不能替代现场验收。

## 场景要求

- **绘画**：检查笔尖接触、桌面高度、运动范围和力限制，避免工具或机体碰撞。
- **棋类**：复核棋盘状态、棋规、取放目标、抓取状态；视觉不确定时停止，不凭假设继续。
- **导航**：处理定位失效、障碍物、动态场景、地图变化和任务超时；目标点不等于可安全通行的路线。

## 记录与数据

每个技能文档应区分本地预览、仿真验证和真机验证，并记录硬件型号、软件版本、配置及已知限制。仅在获得授权后公开现场图像、地图和日志。密钥与机器人访问凭据由本地环境或密钥管理器提供，不进入 Git。

出现异常时按现场急停与隔离流程处理；自动重试应有次数限制，且不能在环境状态不确定时重复运动。
